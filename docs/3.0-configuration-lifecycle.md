# 3.0 配置对象生命周期

最后更新：2026-08-16

## 顶级规则

所有由管理员创建、并会持续影响系统行为的配置对象，都必须同时提供：列表、详情、新增、编辑、停用/启用和删除能力。编辑接口使用明确的 `PUT` 或 `PATCH`；`PUT` 只能更新已存在对象，路径 ID 不存在时返回 404，不能暗中创建新对象。

删除必须先检查依赖。存在引用时返回 409，并提供阻塞对象类型和 ID；控制台应给出可理解的处理建议。密钥留空表示保留原凭据，输入新密钥表示通过 Governance Center 轮换，任何读取接口都不返回明文。

## 当前覆盖

| 配置对象 | 所属中心 | 生命周期 |
| --- | --- | --- |
| Channel Account / Route | MG | 新增、编辑、探测、启停、删除；通道删除保留历史消息 |
| Context Source / Bot Binding | CH | 新增、编辑、启停、删除；系统托管 transcript 不允许人工删除 |
| Model Provider / Deployment / Routing Policy | MH | 完整 CRUD、探测、失败切换；Provider、Deployment 删除有依赖保护 |
| Capability Package | CR | 版本化导入、冲突处理、启停、卸载；包内容不做无版本原地编辑 |
| Capability Binding | CR | 完整 CRUD，可配置触发器、凭据引用和扩展 JSON |
| Bot | Runtime | 完整 CRUD；系统助手和仍绑定通道的 Bot 受保护 |
| Scheduled Task | Scheduler | 完整 CRUD、启停、立即执行、运行日志和下次执行时间 |

控制台默认展示高频字段；每个复杂配置表单必须提供明确的“高级配置”入口，承载作用域、重试、扩展 JSON、请求头、价格、策略和安全模式等低频参数。隐藏到高级入口不等于删除能力。

## 非 CRUD 数据

消息、执行、投递、调度运行、审计日志、用量记录和诊断记录是不可变运行事实。它们提供 list、detail、query、retry、cancel、export 或 retention cleanup，而不提供任意编辑。资源删除继续通过引用计数、清理计划和保留期执行，不开放绕过治理的裸删除。

## 验收要求

1. 新增后可在列表看到并重新打开编辑。
2. 编辑不丢失未出现在基础表单中的高级字段和凭据引用。
3. 删除无依赖对象成功；删除被引用对象返回 409 和阻塞信息。
4. 错误 ID 的 `PUT` 返回 404。
5. 桌面和移动端均可发现高级配置入口，展开后无溢出或文字裁切。
6. 自动验收产生的临时配置在结束时清理，不污染生产租户。
