# QuarkfanTools 3.0 Implementation Program

本文是 3.0 从蓝图进入实现、部署和验收的执行总纲。它以现有 MG / CH / MH / CR 设计为边界，以当前 `QuarkfanTools-Single` 2.3.2 的能力面为迁移基线。

## 1. 交付目标

首个可用版本必须同时具备：

- 可在 Linux 服务器通过 Docker Compose 启动、升级、备份和恢复。
- 带账号密码、会话、角色和审计的 Web Dashboard。
- MG、CH、MH、CR、Runtime、Scheduler、Resource、Governance 的真实服务边界。
- 飞书消息接收、路由、处理和回复的端到端闭环。
- 多 Provider、多模型类型、轮流/随机/固定路由和失败切换。
- Skill、MCP、Suite、Workflow、自定义应用、Browser、Media 的统一注册和治理。
- 可查询的消息、会话、任务、调用、能力、资源、策略和审计记录。
- Playwright 浏览器执行、持久会话、人工认证等待、敏感动作审批、截图/trace/视频产物。
- FFmpeg 异步媒体任务、进度、取消、重试、产物和诊断。
- 从 2.x 导出的配置和能力资产到 3.0 的受控导入路径。

“可用”不以页面存在为标准。每个能力必须有真实 API、持久状态、失败语义、管理可见性、测试和部署验证。

| Model-Hub | `model-hub` | 4103 | provider/model/routing/fallback/inference/usage |
| Capability-Registry | `capability-registry` | 4104 | manifest/package/binding/conflict/diagnostic |

新增独立模块：

| 仓库 | 服务 | 默认内部端口 | 主要职责 |
| --- | --- | ---: | --- |
| Platform-Contracts | npm package | - | envelope、DTO、schema、client、service kit |
| Runtime-Center | `runtime-center` + worker | 4105 | runtime adapter、agent/tool loop、workspace、execution |

## 3. 统一技术基线

- Node.js 22 + TypeScript 5，ESM。
- Fastify 作为中心服务 HTTP 基线，Zod/JSON Schema 作为输入输出合同。
- PostgreSQL 16 作为事实存储和队列基础；首版采用 `pg-boss`，不额外引入 Redis。
- 对象和大文件首版使用受管本地卷，接口保持 S3 compatible，后续可切换 MinIO/S3。
- Better Auth 承载 Dashboard 账号密码、会话和管理能力；BFF 负责浏览器会话到内部服务身份的转换。
- Pino JSON 日志 + OpenTelemetry trace/metric 语义；所有链路保留 `requestId`、`correlationId`、`causationId`。
- Playwright 是确定性浏览器执行底座；LLM 浏览器 agent 必须通过 Runtime adapter 和治理检查调用它。
- FFmpeg/ffprobe 是媒体执行底座；媒体任务进入持久队列，禁止把任意用户参数拼成 shell 字符串。
- Docker Compose 是首个服务器交付形态；公网只暴露反向代理和 Dashboard。

## 4. 关键实现决策

### 4.1 单数据库，中心独立 schema

首台 2C/4G 服务器只运行一个 PostgreSQL 实例。每个中心拥有独立 schema、迁移和数据库角色，不能直接跨 schema 读取；跨中心业务访问必须走 API。这样控制资源占用，同时保留未来拆库能力。

### 4.2 无 Redis 的持久任务

Scheduler、Runtime Browser Worker 和 Media Worker 共用 PostgreSQL 队列机制，但使用不同 queue 和并发限制。任务定义、运行事实和业务结果仍保存在各自中心表中，队列表不是业务事实的唯一来源。

### 4.3 Dashboard 只访问 BFF

浏览器不直接访问中心服务。Platform Console 完成登录、CSRF/origin 检查、RBAC、审计和响应裁剪，再用短期内部身份调用各中心。中心端口只在 Docker internal network 可见。

### 4.4 凭据不进入普通配置

Provider key、channel secret、OAuth token 和外部系统凭据只以 `credentialRef` 出现在中心数据中。首版 encrypted credential store 使用服务端 master key；日志、trace、诊断包和 API 默认不返回明文。后续可替换 Vault/云密钥服务。

### 4.5 Runtime adapter

Runtime Center 不绑定单一 SDK。首批 adapter：

- `claude-agent-sdk`：迁移当前 2.x Claude Agent SDK 运行方式。
- `openai-agents`：支持 OpenAI Agents SDK 的 agent/tool/guardrail/session 模型。
- `model-tool-loop`：只依赖 MH 的通用 tool calling，作为兼容和降级 runtime。

所有 adapter 输出统一 execution event、tool request、approval checkpoint、usage 和 final result。

### 4.6 Browser 与 Media 是受管 capability provider

浏览器和媒体不是 Runtime 内的特殊分支。CR 发布 capability manifest，Runtime 创建执行请求，Governance 检查，Resource 分配 workspace/artifact，专用 worker 执行，Scheduler 提供队列/重试，最终事件写回 Runtime 和 MG。

## 5. 纵向里程碑

### M0：共同基础

- Platform Contracts、service kit、错误语义、内部认证、配置、迁移、健康检查、日志和测试模板。
- Console 登录、首个管理员初始化、用户/角色管理和中心状态页。
- Compose 启动 PostgreSQL、中心服务和反向代理。

### M1：消息到回复

- MG 飞书 adapter、消息标准化、去重、store、route、delivery。
- MH Provider/Model、选择、调用、失败切换、usage。
- Runtime model-tool-loop、会话、工作区、执行事件。
- Dashboard 可配置 Bot、Provider、模型和路由，可查看消息、execution 和 delivery。

### M2：上下文与能力

- CH source/record/binding/retrieve、memory candidate/confirmed/forget/freshness。
- CR Skill/MCP/App/Suite/Workflow manifest、binding、conflict、diagnostic。
- Runtime 注入 CH 上下文和 CR 能力；Governance 产生策略和审计记录。

### M3：调度、浏览器、媒体和资源

- interval/daily/weekly/cron、立即执行、重试、暂停、运行日志、历史补处理。
- Playwright isolated session、storage state、trace、download、screenshot、人工认证等待和审批续跑。
- FFmpeg 20 类操作、队列、进度、取消、产物、限额和清理。
- 一键排障包、文件缓存、清理策略、CPU/内存/磁盘和服务状态。

### M4：2.x 迁移和生产验收

- 配置/Skill/App/Suite/Workflow 导入器和冲突解决。
- 飞书、企业微信、命令、定时任务、本地 Web 对话、Builder/Assistant 的迁移验收。
- 备份恢复、安全、故障注入、重启恢复、浏览器/媒体资源上限和 E2E。
- GitHub 全仓库推送、服务器部署、安装/运维/排障/升级文档。

## 6. 首台服务器资源预算

目标服务器为 2 vCPU / 3.6 GiB RAM / 49 GiB disk：

- PostgreSQL：内存上限约 512 MiB。
- 各 Node API：常态 96-192 MiB，总体约 1.2 GiB 内。
- Browser worker：并发默认 1，任务内存上限 1 GiB。
- Media worker：并发默认 1，FFmpeg 线程默认 1-2。
- 无本地大模型服务；Ollama/vLLM 只作为远端或未来独立节点 provider。
- 日志轮转、artifact TTL 和磁盘水位保护默认启用。

## 7. 发布阻断项

以下任一项未通过，不得标记可用版本：

- 默认管理员密码未强制修改，或敏感配置可从普通 API/日志读取。
- 任一中心缺少 readiness、迁移、备份恢复或结构化错误。
- 消息/任务/浏览器/媒体在服务重启后丢失状态或产生重复副作用。
- 多 Bot、多账号、多 workspace 的数据隔离测试失败。
- Browser/FFmpeg 可通过参数注入任意 shell，或可越过 workspace。
- Dashboard 存在未认证管理接口，内部服务端口直接暴露公网。
- 2.x 迁移矩阵中标为首版必须的能力没有真实闭环或明确受控降级。
