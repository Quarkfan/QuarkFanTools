## Controlled degradation

- WeCom historical desktop polling is not emulated on Linux. MG reports the adapter as planned/degraded and preserves a remote-worker migration path.
- DingTalk is explicitly unsupported until a real adapter exists.
- Existing desktop Chrome profiles are not mounted into the server. Browser authentication uses encrypted managed sessions and an external-auth checkpoint.
- Claude execution requires an externally configured Claude runtime; other runtime adapters remain available.

These states are acceptable only while they remain visible in API/UI capability status and never report false success.

## Hardening status

- Every independently deployable process rejects a missing or weak internal service token at startup.
- Browser session encryption requires a base64 source key that decodes to exactly 32 bytes.
- Compose services drop all Linux capabilities unless a service explicitly proves it needs one.
- Backups cover PostgreSQL and every persistent application volume, include SHA-256 and archive checks, exclude live secrets, and state the external secret-escrow requirement.
- Restore is guarded, re-verifies its input, creates a pre-restore backup and ends with a full smoke check.
- Console status distinguishes process liveness from dependency readiness and reports version, latency and last-check time.
- Diagnostic ZIP collection uses bounded metadata, recursively redacts structured values and redacts common secret forms inside log text.
- Acceptance and Dashboard QA scripts use exit traps to remove temporary accounts/services, tenant-scoped test data and attributable persisted artifacts, and restore production Browser Worker policy after success, failure or interruption.
- Dashboard QA opens every contextual guide dialog, checks its three guidance sections, closes it with Escape, verifies each configuration form ends with one buttons-only submit footer, requires real health labels with hover-only check metadata for detectable model/channel/plugin records, then checks advanced configuration, explicit control dimensions, overflow and clipping at desktop/mobile viewports.

## Remaining evolution

The implemented extension baseline intentionally does not support arbitrary npm package loading or in-process third-party code. Future work may add signed package installation, remote Runtime Providers such as DeepSeek Harness, richer ledger projections and multi-version package rollback beyond the current durable built-in Provider admission state. Those are additive evolution points, not blockers for the current built-in Provider architecture.
